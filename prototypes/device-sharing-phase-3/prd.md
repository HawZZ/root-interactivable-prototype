## 1. 摘要

家人尚未注册时，设备拥有者无法一次完成分享。三期支持自研、Tuya 先邀请，家人注册登录后直接获得共享设备；Meari 发送注册指引，注册后由拥有者重新分享，并提供通知补发及邀请管理。

## 2. 需求范围

| Feature | 本需求要做什么 | 用户可见结果 |
| --- | --- | --- |
| F01 发起未注册分享 | 复用添加共享入口，按账号地区固定输入类型，校验后按设备能力创建邀请或发送注册指引 | 自研/Tuya 出现待注册记录；Meari 提示注册指引已发送 |
| F02 通知与注册引导 | 定义三厂商邮件、短信和 H5，支持完整注册及下载/打开 APP | 接收者理解受邀账号、建议地区及注册后的下一步 |
| F03 注册后接收共享 | 自研/Tuya 在注册登录后校验邀请并直接建联，失败后于接收者下次启动 APP 重新获取；Meari 注册完成后联系拥有者重新分享 | 自研/Tuya 有效关系出现在设备列表；Meari 重新分享后进入接受/拒绝流程 |
| F04 通知补发 | 自研/Tuya 从待注册记录补发；Meari 在添加共享页重复提交同账号补发，统一执行冷却、次数及幂等控制 | 在允许条件下再次收到通知，原邀请与额度保持一致 |
| F05 共享记录管理 | 展示三种有效状态及单设备额度；按状态撤销邀请、移除邀请或取消共享 | 操作成功才移除记录并释放额度，失败保留原记录 |
| F06 接收入口一致性 | 清理自研/Tuya 接收侧历史确认弹窗及触发入口；启动、登录、前台恢复及通知入口按当前有效关系处理 | 自研/Tuya 直接接收共享，Meari 有效已注册邀请仍需接受/拒绝 |

## 5. 核心流程与规则

### 5.1 S01：向尚未注册的家人发起分享

```mermaid
flowchart TD
  A["开始"] --> B["分享者：进入添加共享，输入账号、勾选合规并确认"]
  B --> C["系统：校验账号、现有记录、设备额度、频控与幂等"]
  C --> D{"校验通过？"}
  D -- "否" --> E["保留输入并反馈对应原因；不创建邀请、不发送"] --> Z["结束"]
  D -- "是" --> F{"账号已注册？"}
  F -- "是" --> G["按二期分享：自研/Tuya 直接建联，Meari 待接受"] --> Z
  F -- "否" --> H{"设备厂商？"}
  H -- "自研" --> I["保存待注册邀请，发送通知"]
  H -- "Tuya" --> J["分享者生成链接，包装并保存；限成功建联一次；发送通知"]
  H -- "Meari" --> K["只发送注册指引；不调用 SDK 创建邀请"]
  I --> L["提示已发出；共享管理保留一条待注册记录"] --> Z
  J --> L
  K --> M["提示指引已发送；关闭后停留添加共享页"] --> Z
```

分享者的账号地区决定入口：中国只输入手机号并发送短信，海外只输入邮箱并发送邮件，页面不提供类型切换。同设备同账号已有待注册、待接受或共享中记录时阻止重复创建；待注册记录引导从共享管理补发。Meari 未注册同账号再次提交进入 S03 的指引补发流程。

自研/Tuya 创建的待注册记录无设备权限，占一条额度且不按时间自动到期；Tuya 包装链接保留同一码，成功建联次数固定为 1。Meari 只保存通知历史，不创建共享记录、不占额；分享结果需说明注册后联系分享者重新分享。发出邀请与发出指引都不能展示为设备已共享。

### 5.2 S02：接收通知、完成注册并进入 APP

接收者先打开邮件或短信详情，再点正文中唯一 H5 链接。打开通知本身只展示内容。H5 首屏明确分享者、设备、脱敏账号、建议地区和厂商对应的下一步，注册为主操作，下载/打开 APP 为并行路径。

| 流程触点 | 布局与格式 | 此处需要表达的内容和操作 |
| --- | --- | --- |
| 邮件收件箱/详情 | 列表展示 Momcozy、主题、摘要；详情白底居中单列，移动端左右留白至少 16px，段落左对齐，主按钮全宽、文字居中 | 分享者与设备 → 厂商邀请说明/注册指引 → 账号和地区建议 →「打开注册网页」→ 自动发送及帮助页脚；只放一个 H5 链接 |
| 短信会话 | 系统短信内一条连贯正文，不插入图片、二维码或第二个链接 | 【Momcozy】→ 分享者与设备 → 厂商后续动作 → 地区建议 → 唯一 H5 链接；点击正文链接进入 H5 |
| H5 首屏 | 居中单列，左右 16px 留白，小屏纵向滚动、桌面窄列 | 标识 → 标题/设备说明 → 提示区 → 脱敏账号/地区建议 →「立即注册」→ 下载标题/二维码/两类商店按钮 → APP 注册登录指引 |
| H5 注册 | 使用完整既有账号注册模块；字段顺序见 F02 | 预填账号和地区，验证码按账号类型发送；有效必填项及协议全部通过后才允许创建账号 |
| 注册完成 | 结果标题 → 结果说明 → 打开 APP 主按钮 → 二维码及商店按钮 | 自研/Tuya 提示登录 APP 后接收；Meari 提示联系分享者重新分享；邀请已失效时仍允许注册但不能通过原邀请接收设备 |

三厂商、两通知渠道及 H5 的完整文案、变量来源、布局和格式见 [通知与注册模板](https://momcozy-in.feishu.cn/docx/VUCsdnhXGoNexBxH4WdcKWSVnZV)，该附录是本试稿的模板定义。邮件/短信补发沿用同厂商同模板；模板语言沿用分享者 APP 语言，英文须逐项保持语义。地区文案统一为：“建议选择共享者的国家或地区「{owner_region}」注册并登录；如果选择其他国家/地区，可能无法查看共享设备及设备数据。”

点击注册后，推荐 Plan A 在当前 H5 会话复用完整注册模块；技术备选 Plan B 在同标签页跳转既有注册页，携带签名邀请上下文、预填信息及 `return_url`，完成后回到邀请完成页重新校验。A/B 是待评审的承载方案，不在用户界面提供切换；禁止 iframe、新窗口及丢失邀请上下文的普通外链。两方案使用同一字段及校验，返回时保留邀请来源，Plan A 还保留未提交表单。

修改账号或地区后提交需二次确认：继续注册不撤销原邀请；账号不同无法建立原共享关系，地区不兼容可能无法查看设备及数据。取消返回修改，继续则完成账号注册并复核邀请。国内 Android 固定中国、不展示地区选择。注册过程不锁定接收资格，邀请被撤销也不阻止普通注册。

```mermaid
flowchart TD
  A["开始：接收者已注册并登录 APP"] --> B["系统：按已验证登录身份复核邀请或注册指引上下文"]
  B --> C{"上下文有效且账号匹配、地区兼容？"}
  C -- "否" --> D["按原因处理：不开放设备权限，不删除仍有效邀请"] --> Z["结束"]
  C -- "是" --> E{"存在何种邀请？"}
  E -- "自研待注册" --> F["直接建联"]
  E -- "Tuya待注册且码未用尽" --> F
  E -- "Meari未注册指引" --> G["提示联系分享者；分享者重新发起已注册邀请"]
  G --> H["接收者接受或拒绝 Meari 邀请"]
  H --> I{"接受并建联成功？"}
  I -- "是" --> K["原位转共享中，展示设备"] --> Z
  I -- "否" --> J["拒绝成功留在当前页；失败按二期反馈"] --> Z
  F --> L{"最终关系成立？"}
  L -- "是" --> K
  L -- "否" --> M["保留原邀请，不开放权限；下次启动 APP 重新获取并校验"] --> Z
```

账号匹配与地区兼容分开判断，国家代码不同不能直接判失败，美国与加拿大等同数据中心组合可建联。账号不匹配或地区不兼容时，APP 登录后不新增 Toast 或失效提示；仍有效邀请不撤销，可改用受邀账号及兼容地区登录后重新拉取。邀请撤销、Tuya 码用尽时不能新建关系，重复成功回执只同步原关系。

自研/Tuya 最终关系成立才展示设备；不增加处理中页面或接收方接受/拒绝操作。Tuya 仅最终建联成功消耗一次，注册、拉码及校验/执行失败不消耗次数。建联失败时保留原邀请及待注册记录、占额和未使用的 Tuya 码次数，不开放设备权限，不要求分享者重新发起；提示“暂时无法添加设备，请下次启动 APP 时重试。”被分享者下次启动 APP 时，系统重新获取原邀请，按已验证登录身份、受邀账号、数据中心兼容性、设备归属及邀请状态复核后再次尝试建联；Tuya 还须确认原码未用尽。仍失败则继续保留待注册状态；邀请已撤销、设备归属已变化或其他终态失效时不得恢复。接收方不新增手动重试按钮。

### 5.3 S03：对方未收到通知，分享者主动补发

分享者从自研/Tuya 待注册记录选择“重新发送通知”；Meari 从添加共享再次提交同一账号。后台先检查距离上次成功发送是否满 5 分钟，再核对生命周期次数与目标固定日配额，当日第 3 次实际发送前完成人机验证，通过后才发送。

| 此次补发步骤 | 判定与结果 |
| --- | --- |
| 确定原通知上下文 | 自研沿用原邀请，Tuya 沿用原码；Meari 按分享者、设备、规范化接收账号识别同一轮指引 |
| 校验发送间隔 | 未满 5 分钟不发送，提示“请等待 5 分钟后再发送” |
| 校验生命周期 | 首发加最多两次补发，最多 3 次实际通知；跨日不重置同一生命周期次数 |
| 校验固定日配额 | 按分享者账号＋设备＋规范化接收账号，每自然日最多 3 次；首发、补发及撤销重建合并计数；统一后台业务时区，未配置时 UTC+8 |
| 当日第 3 次发送 | 人机验证成功才继续；失败或取消不发送、不计数，可再次验证 |
| 渠道受理 | 邮件/短信服务受理成功计一次，明确发送失败不计；同一幂等键重试最多发送和计数一次 |
| 回到管理/发起页 | 补发不新增邀请、不增加额度、不生成 Tuya 新码或恢复码次数；Meari 仍无共享记录 |

生命周期用尽或固定日超限提示“操作过于频繁，请稍后再试”；验证失败提示“验证未通过，请重试”；发送失败提示“通知发送失败，请重试”。频控拦截不创建新邀请、不发送、不新增占额。重开 H5、切换地区或重新登录不触发补发。

撤销后向其他账号发起使用该账号的独立目标配额；向同账号重新发起获得新的邀请生命周期，但继承原目标的冷却、当日计数与通知历史。固定日切换只重置当日配额，Meari 同一轮指引生命周期也不重置。

### 5.4 S04/S05：终止共享或从历史入口恢复

分享者在记录菜单选择与当前状态对应的终止操作并二次确认。前端等待服务端和对应 SDK/关系服务最终成功，才移除记录及释放额度；明确失败、超时和未知错误码均保留原记录、额度与权限，可再次操作，不展示处理中或结果未知状态。

撤销待注册邀请后旧链接不能建立关系；移除待接受邀请后旧通知和 SDK 事件不能恢复接受；取消共享成功后接收者失去权限，缓存和迟到事件不能恢复访问。服务端保留通知历史和终态供校验。

接收者启动、登录、前台恢复或打开系统通知/消息中心时，自研/Tuya 直接按当前有效关系展示，不唤起接受/拒绝弹窗；旧通知本身不能创建关系。Meari 仅有效的已注册待接受邀请恢复确认弹窗。分享者提交前的确认、建联后通知、设备版本与权限校验继续执行。

## 6. 功能详情

### 6.1 F01：发起未注册分享

入口为既有共享管理的“添加共享”。合规勾选确认接收者为共同监护人或已授权照护者。单设备可见记录达到 20 条时禁用添加共享；服务端再次校验额度及重复记录。正常 APP 不显示厂商，厂商只影响后台分流和对应结果。

| 信息/字段 | 来源 | 使用与约束 |
| --- | --- | --- |
| 设备及拥有者 | 当前设备、已登录拥有者身份 | 校验设备归属与分享权限；归属变化不能沿用旧邀请 |
| 接收账号 | 分享者输入，按既有规则规范化 | 中国手机号、海外邮箱；格式有效且合规勾选后可提交；规范化值用于重复校验、通知及建联 |
| 合规确认 | 分享者勾选 | 未勾选不能提交 |
| 分享者 Nickname、设备名 | 发起时快照 | 通知与 H5 同一快照，不能写死示例人物或设备 |
| 分享者国家/地区、APP 语言 | 发起时账号与 APP 设置 | 地区建议与数据中心映射分别使用；通知和 H5 沿用语言 |
| 受邀账号注册状态、设备厂商 | 后台校验 | 选择已注册分享、待注册邀请或 Meari 注册指引 |

自研/Tuya 成功发起后保留一条待注册记录并说明邀请已发出；Meari 用单按钮强调弹窗说明注册指引邮件/短信已发送或重新发送，提醒注册后联系分享者，关闭后停留添加共享页。

### 6.2 F02：通知与完整注册

Tuya 分享码的单次成功建联限制由后台执行，不在邮件、短信、H5 或 APP 面向用户的文案中展示“仅接收一次”“一次性使用”等说明；不改变每码最多成功建联一次的业务规则。

| 注册字段/信息 | 必填性 | 行为与约束 |
| --- | --- | --- |

### 6.3 F03/F06：建联、状态机与历史入口

```mermaid
stateDiagram-v2
  [*] --> pending_registration: 自研/Tuya 邀请创建
  pending_registration --> pending_registration: 建联失败保留；下次启动 APP 重新获取并校验
  pending_registration --> active: 受邀账号登录且校验通过、最终建联成功
  pending_registration --> terminated: 拥有者撤销成功
  [*] --> pending_acceptance: Meari 对已注册账号发起邀请
  pending_acceptance --> active: 接收者接受且最终建联成功
  pending_acceptance --> terminated: 拒绝/移除邀请/删除设备成功
  active --> terminated: 取消共享/主动退出等二期终止路径
  terminated --> [*]: 前端移除，服务端保留终态
```

| 可见状态 | 适用设备/对象 | 显示信息 | 权限 | 占额与菜单 |
| --- | --- | --- | --- | --- |
| 待注册 `pending_registration` | 自研/Tuya 未注册邀请 | 脱敏邮箱或手机号 | 无 | 1 条；重新发送通知、撤销邀请 |
| 待接受 `pending_acceptance` | Meari 已注册邀请 | Nickname＋脱敏账号 | 无 | 1 条；移除邀请 |
| 共享中 `active` | 全厂商有效共享 | Nickname＋脱敏账号 | 二期共享权限 | 1 条；取消共享 |

三种可见状态合计最多 20 条，状态转换原位更新。终止为服务端校验状态，不在管理页面显示终态或筛选项。自研/Tuya 待注册不按时间到期；Tuya 原码限成功建联一次，码失效不取消已建关系。Meari 已注册待接受持续有效，仅接受/拒绝、移除邀请或删除设备终止。Meari 未注册指引没有邀请状态。

建联后继承二期设备最低 APP 版本、设备列表、权限矩阵、主动退出、取消共享、网络异常、并发及旧通知失效规则；设备无“共享”标识、跳过 onboarding。关系只提供 ACL 与权限，实际控制依赖产品/面板已有本地蓝牙或云端能力。系统 Push 和消息中心沿用二期触发，建联不重复发送邀请邮件/短信；已注册手机号不新增短信。

### 6.4 F04：邀请、通知与频控的信息关系

| 信息对象 | 与其他信息的关系 | 保留与变化 |
| --- | --- | --- |
| 自研待注册邀请 | 关联拥有者、设备、规范化受邀账号、地区/语言快照及通知历史 | 补发沿用邀请，建联原位转共享中，撤销成功才移除前端记录 |
| Tuya 待注册邀请 | 同上，并关联一个云端保存的包装分享码上下文 | 注册及拉码不耗次，最终成功耗一次，重复成功回执保持同一关系 |
| Meari 注册指引轮次 | 按拥有者、设备、规范化接收账号关联一轮通知历史 | 没有共享邀请和管理记录；跨日不重置该轮生命周期计数 |
| 通知历史 | 每次渠道受理关联原邀请/指引轮次与目标固定日配额 | 撤销、跨日和重建不删除历史；明确失败不计实际发送 |
| 请求幂等信息 | 同一操作重试对应同一幂等键 | 不重复通知、不重复计数、不重复建联或占额 |
| 最终共享关系 | 关联设备及已验证接收身份，承载共享权限 | 仅关系成立开放权限；终止成功后旧链接及迟到事件不能恢复 |

以上为产品信息关系，字段接口、签名、并发原子处理与错误码由技术契约定义。

### 6.5 F05：按记录状态终止

| 当前状态 | 操作 | 成功结果 | 失败/超时/未知错误码 |
| --- | --- | --- | --- |
| 待注册 | 撤销邀请 | 移除记录、释放 1 条额度，旧邀请不可再建联 | 保留原记录与占额，可重试 |
| 待接受 | 移除邀请 | 移除记录、释放 1 条额度，旧通知/SDK 事件不可再接受 | 保留原记录与占额，可重试 |
| 共享中 | 取消共享 | 移除记录、释放 1 条额度并撤销接收者权限 | 保留原关系、占额和权限，可重试 |

每项均需二次确认，不能乐观删除；成功后可重新发起，重新发送仍经过账号、额度和频控检查。
