## 补充候选规则：导入异常与空白

这是Controller提出的交互与验收设计，非用户逐字指定；具体解析库、接口及平台权限继续归原技术职责。

- Excel本期采用`.xlsx`模板，CSV为UTF-8（可含BOM）；`.xls`、`.xlsm`及其他扩展名不作为支持格式，选择时提示改用模板格式。文件实际结构须可按所选格式解析，不只检查后缀。
- Excel只接受一个非空工作表，空表忽略；有多个非空工作表则整单拒绝并定位表名，不猜测目标表。
- 一行表头加一条对象数据行，单元格内换行不算新增数据行；16个固定语言代码可缺列，缺列保留表单值。未知/重复语言列、多个数据行、损坏或错误编码、公式单元格（包括有缓存结果的公式）整单拒绝，绝不执行公式，不部分应用，提示可定位的表/行/语言和原因。
- 模板语言格全部为空。导入非空文本才覆盖；空、纯空白或缺列均保留当前表单值（包括现有非英语译文和自定义英语）。判断空白不改写有效Markdown源码，保存保留原始文本和换行；合并后英文去空白判断必须非空。表单手动清空非英语则改为未配置并兜底英语。
- 空文件、只有表头或无有效变更时提示“无变更”，禁止执行应用，表单和已保存数据零改写；不是成功导入，更不是清空命令。
- 文件大小、每格长度和预览资源上限的具体数值由技术依据现有平台确定，并在开发验收前记录和显示。超限预检整单拒绝且零改写；QA必须用技术确定的上限L及L+1验证边界，不以此要求用户决定数值。
- 预检展示新增/覆盖/不变/跳过及差异；应用仅入当前表单，主保存才持久化；取消或错误无部分变更。文件/对象变化须重新预检，提交时重新判断当前对象状态。

## 补充候选规则：Markdown双端验收矩阵

以下是待实施的共同样例与预期，不是已执行结果。必须按同一源码、语言、渲染策略版本在平台预览和APP逐项核对；不能以普通文字样例替代全部验收。必需能力为标题、列表、强调、链接和换行。表格、代码块、图片不增加本期必需能力；技术依据APP现有能力确定支持或安全文本降级，在实施验收前冻结两端共同元素清单、预期展示及URL策略，选定后两端不得各用一套。界面像素及字体不要求相同，语义、内容、结构和安全结果须相同。

| ID | 固定样例/生成规则 | 必需验收结果 |
| --- | --- | --- |
| MD01 | `# Update` + 空行 + `## Details` | 两端同级标题、完整文字 |
| MD02 | `- Fix A` + 换行 + `- Fix B`；另测`1. A`、`2. B` | 两端同序完整列表 |
| MD03 | `**Fixed** and *improved*` | 同一强调语义，不遗漏文字 |
| MD04 | `Line A` + 两个空格 + 换行 + `Line B`；另测空行分段和普通源码换行 | 强制换行及分段一致；普通换行按冻结策略一致；导入后源码不变 |
| MD05 | `[Details](https://example.com/release)` | 相同链接文字和目标；合法链接按共同URL策略处理 |

| MD07 | 表格`a\|b`/代码块/图片`![note](https://example.com/note.png)`及不支持语法 | 逐项记录共同能力清单；支持则语义一致，不支持则保留可读文本且不执行、不静默丢内容；图片加载与链接URL策略技术冻结后逐项验收 |
